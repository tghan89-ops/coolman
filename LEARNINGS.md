
## — Payload schema changes: apply DDL directly, never `payload migrate:create`
- **Symptom:** `payload migrate:create` went interactive AND pulled in unrelated schema drift (email_deliveries enum, why_coolman advantages enum) — dangerous to answer blind; hung the terminal.
- **Cause:** This project runs the postgres adapter with `push:false` and keeps NO committed `migrations/` dir. Payload does NOT diff the schema at runtime with push off — it only queries. So `migrate:create` is the only thing that diffs, and it diffs the WHOLE DB, surfacing every pre-existing drift, not just your change.
- **Rule:** For a global/collection schema change, hand-write idempotent DDL (`scripts/sql/*.sql`, `ADD/DROP COLUMN IF [NOT] EXISTS`, `CREATE TABLE IF NOT EXISTS`) that matches Payload's exact naming, apply with `psql -f`, then reseed via a `tsx` script calling `payload.updateGlobal`. Group sub-fields → `group_field` columns (tabs add no prefix); BM field `xBM` → `x_b_m` (nullable); arrays → table `parent_group_array` with `_order int NN, _parent_id int NN FK→parent(id) ON DELETE CASCADE, id varchar PK`, required fields NOT NULL, `_order`/`_parent_id` btree indexes. Copy an existing array table's `pg_dump --schema-only` as the template. burned 2026-06-20

## Puck visual editor build (2026-06-21)
- **New top-level app routes must live in a route group that renders `<html>`/`<body>`.** This project's root `app/layout.tsx` just `return children`; `(frontend)` and `(payload)` group layouts each provide `<html>`/`<body>`. A route placed directly under `app/` (e.g. `app/puck-editor/`) renders with no html/body → Next "Missing <html> and <body> tags in the root layout". Fix: put it in a group, e.g. `app/(editor)/puck-editor/` with `app/(editor)/layout.tsx`. burned 2026-06-21.
- **`@measured/puck` is deprecated → use `@puckeditor/core`** (stable 0.21.x; React 19 peer-supported). `DropZone` is superseded by `slot` fields. `Render` for RSC pages comes from `@puckeditor/core/rsc`. burned 2026-06-21.
- **Pre-existing schema drift**: committed migrations don't rebuild from an empty DB (`posts` missing mid-chain), and config has un-migrated enums (`enum_email_deliveries_email_type`) plus an orphaned `enum_why_coolman_page_advantages_icon_key`. `migrate:create`/push hang on interactive create-vs-rename prompts because of the orphan. Clean this up before any new migration deploys. Scratch testing built schema via `PAYLOAD_DB_PUSH=true` against an EMPTY db (no drift, no prompts). burned 2026-06-21.
- **Puck inline edit (`contentEditable: true`) works inside `array` sub-fields too**, not just top-level fields — Puck's inline transform walks the prop path. So an editable repeater (Stats/FAQ/Steps) needs NO slot; keep the clean `array` + grid render and just render `{item.field}` directly (it's a string on the server, a live editable node in the editor). Slots, by contrast, wrap each child in a drag hitbox in the editor, so grids-of-slot-items look stacked while editing. burned 2026-06-21.
- **Puck left-palette icons: use `overrides.drawerItem` (`componentItem` is deprecated and warns).** Editor-only override `({children, name}) => …`; keep it in a `'use client'` file imported only by the editor client, never by the server `<Render>` path, so `lucide-react` never ships to public pages. There is NO per-component `icon` in `ComponentConfig` and no icon on `categories`. burned 2026-06-21.
- **Puck output quality = block quality, NOT the tool.** A generic-block rebuild of a hand-tuned page (the home) looked cheap — generic blocks each re-apply their own container/padding and approximate bespoke composition. The fix for a flagship page is the LOCKED-LAYOUT + EDITABLE-CONTENT model: bespoke blocks whose render is the EXACT live-section markup (so it's pixel-identical), locked via `permissions: { drag/duplicate/delete:false }` per component + `<Puck permissions={{ insert:false, ... }}>` globally, with text/images as `contentEditable` fields. Structure frozen, content editable. Live data goes in via Puck `metadata` (passed to `<Render>`/`<Puck>`, read as `puck.metadata` in render) — keeps catalogue read-only, no editable product/price block. burned 2026-06-21
- **MediaField upload**: photo upload = multipart `POST /api/media` with `file` + `_payload` (JSON string of the other fields). Media's `alt` is `required`, so seed it from the filename or the create 400s. Collection create is auth-gated (admin session) — the in-editor `fetch` must send `credentials: 'include'`; an unauthenticated POST returns 403. burned 2026-06-21.

## Puck Pages/Navigation deploy to prod (2026-06-21)
- **Hand-applying DDL with `sudo -u postgres psql` makes the app role (`coolman`) unable to read the new tables → live 500 `permission denied for table pages` (aclcheck_error).** Objects are owned by whoever runs the DDL; the app connects as `coolman`, which gets zero privileges on `postgres`-owned tables. Symptom was a 500 on the catch-all `[...slug]` route (and silent fallback elsewhere, because layout wraps nav reads in catch()). Fix: after a manual psql DDL apply, reassign every new object to the app role — `ALTER TABLE public.<t> OWNER TO coolman;` for each new table (owned sequences follow the table automatically; you CANNOT `ALTER SEQUENCE … OWNER` directly — it errors "linked to table"), plus `ALTER TYPE … OWNER TO coolman` for new enums. Better: run the DDL as the app role in the first place. The repo `.ts` migration is unaffected — `payload migrate` connects as `coolman`, so a fresh-DB deploy creates them correctly. burned 2026-06-21.
- **`payload migrate` (plain) refuses non-interactively on this prod because of historical dev-push drift** — it prints "you've run Payload in dev mode … data loss will occur. proceed? (y/N)" and a non-TTY auto-answers no, aborting. The CLI's `--force-accept-warning` flag is wired ONLY to `migrate:create`/`migrate:fresh`, NOT to `migrate`. So on a drifted prod the reliable path is: build the additive DDL from the canonical schema (dev-mode `PAYLOAD_DB_PUSH=true` push into an EMPTY db, then pg_dump the new objects), trim to the delta, TEST on a fresh prod clone in a transaction, apply to prod in a transaction AS the app role (or fix ownership after), then INSERT the `payload_migrations` row manually (`name`, next `batch`) so Payload's bookkeeping stays consistent and a later `migrate` skips it. Commit the matching idempotent `.ts` migration for fresh deploys. burned 2026-06-21.

## Puck review hardening (2026-06-21)
- **Puck 0.21 slot model nests child blocks INLINE in a parent's props, not in `zones`.** A malformed-block sanitizer that only filters top-level `data.content` by known type lets a bad block inside a Section/Columns slot reach `<Render>` and crash the page. Fix: recurse the sanitizer through every array-valued prop (treat any `{type, props}` item as a nested block, filter by known component, recurse). See app/(frontend)/[...slug]/page.tsx. burned 2026-06-21.
- **Payload `read: () => true` exposes drafts via the REST/GraphQL API even if the rendered route filters to published.** Anyone can `GET /api/<collection>` and read draft content. Scope public read to published with a Where return: `read: ({req:{user}}) => isAdmin ? true : { status: { equals: 'published' } }`. The SSR route that needs drafts uses `overrideAccess: true` so it's unaffected. burned 2026-06-21.
- **Editable link fields need render-time href allowlisting.** A `linkField`/custom-URL input stores any string; rendering `<a href={value}>` ships a stored `javascript:`/`data:` XSS (admin-write, but still). Sanitize at RENDER (covers hand-edited puckData), strip whitespace before the scheme probe so `java\tscript:` can't slip past. See puck/safeHref.ts. burned 2026-06-21.
